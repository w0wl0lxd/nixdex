- `nixdex locate --details` against the daemon no longer corrupts records: the delimiter is now appended after the detail fields instead of before them, so a record never splits across the delimiter boundary.
- `/stats` reports `package_count` instead of the misleading `sidecar_entry_count`, which never counted sidecars.
- The history sidecar checks its per-attribute version cap only when it actually adds a version, so re-recording a version an attribute already has no longer fails once that attribute is full. The sidecar is also written to a temporary file and renamed into place, so a failed write leaves the previous sidecar intact.
- Case-insensitive option search no longer allocates a lowercased copy of every attribute and description for every query.
- The TUI Nord theme uses the real Nord palette instead of the Tokyo Night one, Tokyo Night uses its own palette, and `Theme::default()` now agrees with the theme `App::new` starts with. The header block gets the three rows its border needs, so the query line is visible again. Expired search-cache entries are dropped on each tick instead of accumulating for the life of the session.
- Daemon-backed `nixdex locate --json` emits package metadata whether or not `--details` is passed, matching the local `--json` path, so the JSON schema no longer depends on whether a daemon served the query.
- The options sidecar is written to a temporary file and renamed into place, like the history sidecar.
- The TUI Ctrl+J toggle renders real JSON rows instead of re-spaced text columns. The Ctrl+N "quiet" toggle is removed: quiet output has no meaning in an interactive result list, and the toggle changed nothing.
- Every daemon route that returns indexed data or operational detail -- `/locate`, `/nix-locate`, `/search`, `/info`, `/history`, `/options`, `/stats`, `/command` and `/reload` -- now sits behind the same guard `/reload` already had: a configured token must be presented, and without one the route is loopback-only. A daemon bound to a non-loopback address no longer serves the index to any client that can reach it. `/health`, `/ready`, `/version` and `/metrics` stay open.
- The TUI query line updates on every keystroke instead of staying frozen until the search debounce fires, and a result arriving for a query the user has moved on from no longer hides the loading indicator while the current search is still running.
- The sidecar up-to-date check now lists every file the heavy readers map, including the entry store-path table and the path-entry string, offset and store-path tables. Deleting one of those used to leave the index unopenable while the check reported the database up to date.
- `nix-locate` says on stderr when several arguments were joined into one pattern, so a misplaced flag or an expanded shell glob no longer produces a silent no-match. `--quiet` suppresses the note.
- `/history` and `/options` say which sidecar is absent and that `nixdex update` fetches it, instead of a bare "no history database loaded". The daemon still does not download sidecars itself.
- The `parallel_search` benchmark is renamed to `package_search`, which is what it measures; the parallel trigram path and the n-gram cache are not exercised by it.
- `advise_huge_pages` now asks for `MADV_HUGEPAGE` only on Linux, so the `huge_pages` feature builds on macOS again; the portable `MADV_WILLNEED` read-ahead hint still applies everywhere.
- The `miri` job runs again: every test that memory-maps a sidecar, opens a real database, calls into `zstd` or drives a tokio TCP listener carries `#[cfg_attr(miri, ignore)]`, matching the idiom already used in `hydra.rs` and `basename_index.rs`. Miri supports neither `mmap` nor foreign function calls, so those tests aborted the whole run before reaching the logic Miri can actually check.
- The TUI tracks searches by a monotonic request id instead of by `(query, mode)`. Ctrl+R re-runs the same pair, so the pre-reload answer used to stop the loading indicator while the reload was still queued, and a request retired by Escape or Tab left the indicator running forever.
- Escape and Tab clear the record of what was last dispatched, so retyping the query that was just cleared searches again instead of leaving an empty result list.
- A pinned detail pane keeps the keyboard. Typing used to reach `set_input`, which clears the pane, so one keystroke dismissed the pin.
- Ctrl+A now changes what is rendered. It set a flag nothing read, so expanding and collapsing altered only the status line. Expanded rows put name, description and path on their own lines.
- `Enter` is described correctly in the help overlay: it opens the detail pane for the selected result rather than submitting the search, which the debounce already does.
- Ctrl+H and Ctrl+J work on terminals that do not support `DISAMBIGUATE_ESCAPE_CODES`. The TUI now requests that mode when the terminal offers it, accepts the Ctrl-modified `Backspace` and `Enter` those terminals send, and binds F1 and F2 as unambiguous alternatives. A plain `Backspace` or `Enter` keeps its own meaning.
- `DaemonClient` sends `Authorization: Bearer` from `NIXDEX_DAEMON_TOKEN`. A daemon started with `--admin-token` refused every data request, while `/ready` stayed open, so the CLI saw a healthy daemon and then had every search rejected.
- `--fuzzy --sort reverse` reverses the whole relevance order. Ties were broken on the attribute name in ascending order, the same direction the default leaves them in, so equally scored packages were not reversed at all.
- Daemon `locate` YAML output opens each match with `---`, so several matches form a valid multi-document stream. The two local YAML renderers in `database.rs` do the same.
- The sidecar checksum download is capped before the body is buffered, matching the artifact download. `Response::bytes` read the whole `.sha256` body first and only then checked the limit; both downloads now share one capped reader that rejects an oversized `Content-Length` and stops mid-stream.
- The options sidecar reader enforces the same per-field caps the builder does. It checked only the attribute length, so a downloaded sidecar could carry an over-long type or description, and the entry-count cap was applied after the whole file had been materialised rather than while reading it.
- `HistoryBuilder::record_version` places each entry by date instead of appending, so the newest-first order the type promises holds whatever order the caller records in. Nothing checked that order and no caller established it.
